stupidbot Commands List
========================

Anyone can say these in chat:
- "Meow, tp to me."          -> bot sends /tpa VOlcarona_Alt
- "Meow, tp me to you."      -> bot sends /tpahere VOlcarona_Alt
- "Meow, stop."              -> bot cancels its current pathfinding goal

VOlcarona_Alt, SpeedStrafe04, or AustrichMC only:
- "Meow, walk to me."          -> bot pathfinds (walks, no teleport) to
                                   whichever of the three sent the message, if
                                   it can see them (says "Can't see <name>" if
                                   not loaded/nearby)
- "Meow, enable totem mode."   -> bot crouches 3 times, equips a Totem of
                                   Undying to its offhand (or says "Totem
                                   required" if it has none), and
                                   auto-re-equips a new totem whenever one
                                   is consumed
- "Meow, disable totem mode."  -> bot says "Totem mode disabled." and stops
                                   auto-re-equipping totems
- "Meow, do <command>"         -> bot runs /<command>
                                   (type the command without a leading slash,
                                   e.g. "Meow, do tpa SpeedStrafe04")
- "Meow, say <message>"        -> bot sends <message> verbatim to public chat
                                   (no leading slash; e.g. "Meow, say hello")
- "Meow, drop item."           -> bot drops whatever it's currently holding
- "Meow, offhand."             -> bot swaps whatever it's currently holding
                                   into its offhand
- "Meow, enable chat games."   -> bot says "Chat game solver enabled." and
                                   resumes detecting/solving Chat Games
- "Meow, disable chat games."  -> bot says "Chat game solver disabled." and
                                   stops detecting/solving Chat Games entirely
                                   (won't answer or record new puzzles until
                                   re-enabled)
- "Meow, toggle chat games."   -> flips the chat games solver on/off from
                                   whatever it currently is
- "Meow, toggle attack mode."  -> flips "attack hostile mobs" on/off (see
                                   notes below) - also a checkbox in the
                                   control panel
- "Meow, build <name> at <x> <y> <z>." (or "Meow, build <name> here." to
                                   anchor at the bot's current position
                                   instead) -> loads schematics/<name>.schem
                                   (or <name>.litematic) and builds it with
                                   that corner as the anchor (walks to each
                                   block, equips the matching item, and
                                   places it -
                                   see notes below)
- "Meow, gather wood (n)."     -> equips an axe if it has one, then finds and
                                   chops down trees (collecting the logs)
                                   until it has n logs or gives up - see
                                   notes below. "Meow, stop." cancels it.
- "Meow, list entities."       -> bot lists every nearby entity (type, name,
                                   display name, position, distance) to the
                                   console/log and says how many it found -
                                   useful for finding the exact name of a
                                   hub NPC on a new server

Automatic (no chat trigger needed):
- Picking up any armor piece (helmet/chestplate/leggings/boots) auto-equips
  it, replacing whatever's currently worn in that slot, and drops the old
  piece on the ground. Only works if the picked-up armor lands in the
  hotbar (a server limitation, not a choice).
- On first spawn, registers via /register smolbrain smolbrain if this is a
  server the bot hasn't joined before (tracked in registered-hosts.json),
  waits 1.5s, then also logs in via /login smolbrain (some auth plugins
  don't auto-login right after registering). Known servers just log in
  directly as usual.
- server-config.json's "version" field is optional - leave it blank/unset
  (the control panel's Save Server field can be left empty) and the bot
  auto-detects the server's real Minecraft protocol version itself by
  pinging it before connecting, instead of guessing. A handful of hosts with
  their own version-specific bugs (currently just play.skeletonmc.com, which
  has broken item-component parsing and forces signed chat on its real
  1.21.11 backend) are hardcoded to a working fallback version regardless of
  this setting; only set "version" explicitly to override auto-detection for
  a specific server.
- If server-config.json sets "hubNpcName" for the current server (e.g.
  ggsmp.net's lobby requires right-clicking an NPC named "GG SMP" to enter
  the main server), the bot searches for an entity whose name contains that
  text after logging in and right-clicks it, retrying every 2s for up to
  20s in case the NPC hasn't loaded yet. Leave hubNpcName blank/unset for
  servers that don't need this (e.g. play.skeletonmc.com).
  If no entity's name literally matches (e.g. ggsmp.net's hub NPC uses a
  scrambled/obfuscated (section-sign "§") fake player username instead of
  literal text), it falls back to targeting whichever "§"-named fake player
  entity sits closest to a nearby armor_stand (these are usually the floating
  nametag/hologram above the NPC's head) - use "Meow, list entities." to spot
  candidates if this heuristic ever picks the wrong one.
- If the main server restarts while the bot is connected, Velocity-style
  networks typically fall the bot back to the lobby on the same connection
  (no kick/reconnect) rather than disconnecting it - the bot detects this
  and automatically retries the hub NPC search/click again, same as it does
  right after login.
- "CHAT GAMES" events: DISABLED BY DEFAULT as of 2026-08-14 - the account
  was banned ("afk farming chat games") for this exact behavior. Use
  "Meow, enable chat games." (or the control panel) to turn it back on at
  your own risk. When enabled: if the bot knows how to solve it (write-out/
  write-out-the-word puzzles, arithmetic "solve" puzzles, "solve for"
  equation systems, or fill-in-the-word/unscramble puzzles matching a word
  already learned in chatgame-words.json), it answers in public chat as
  soon as the puzzle is fully received (no artificial delay). Otherwise the
  puzzle is recorded in chatgames.txt (unanswered) for manual solving later
  - add an "Answer: <value>" line under the question to teach it that exact
  puzzle. Winner/result announcements aren't logged as puzzles, but any word
  they reveal is learned automatically for solving future fill-in/unscramble
  rounds using that same word.

Schematic builder notes/limitations (schematic-builder.js):
- Drop .schem files (Sponge or MCEdit format) or .litematic files
  (Litematica mod format) in schematics/.
- Only *places* blocks - never breaks/clears existing terrain, so pick an
  anchor with clear space, or expect leftover terrain poking through.
- Skips any block it doesn't already have in its inventory (counts as
  "skipped" in the completion message) - stock the bot up first. Logs "Oops
  I ran out of materials" to the console (not public chat) the first time
  this happens in a build (not repeated for every subsequent missing block).
- Build progress ("Building...", "Oops I ran out of materials", "Build
  complete: X placed, Y skipped.") and "Meow, list entities." results are
  only logged to the console/control panel, never sent to public chat - both
  to avoid revealing bot activity and because rapid-fire status messages can
  hit the server's chat rate limit ("You can only send messages every 3.0
  seconds") and get silently dropped.
- Places blocks bottom-up (lowest Y first) for basic support, but doesn't
  reason about block orientation/rotation (stairs, doors, etc. may place
  facing the wrong way).
- When a placement point is too high to path to directly, bridges up to it
  with its own jump+place loop (using any placeable block it's carrying,
  preferring one other than what's actually needed for the current
  placement) rather than mineflayer-pathfinder's own built-in scaffolding,
  which is disabled entirely - it loses a race between the jump physics and
  the network round-trip for equipping/placing almost every cycle, making
  vertical building extremely slow.
- Any bot.pathfinder.goto() call (used here, in wood gathering, and for hub
  NPC approach) is wrapped with an 8s timeout that force-stops pathfinder
  instead of potentially hanging forever - this happened for real during
  testing (a stuck goto() couldn't even be cancelled by "Meow, stop." since
  the cancellation flag is only checked between awaits).
- "Meow, stop." cancels an in-progress build (as well as any pathfinding).

Wood gathering notes/limitations ("Meow, gather wood (n)."):
- Automatically equips the correct tool category for whatever block it's
  about to break (axe for logs, pickaxe/shovel/hoe for anything else this
  gets used on later) if it's carrying one - re-checked before every single
  block, not just once at the start. No crafting - if it doesn't have the
  right tool, it just digs with whatever's already held (fist included)
  instead of refusing.
- Searches for the nearest log-type block (anything ending in "_log" or
  "_stem") within 48 blocks, giving up after 10 seconds if none is found.
- Once a tree is found, every log block connected to it (trunk plus any
  log-only branches) of that exact same wood type is chopped, stopping
  early the instant n total logs have been collected even if part of the
  tree is left standing.
- A log the bot can't actually path to (e.g. sealed behind other blocks) is
  permanently skipped for the rest of that gather instead of being found
  and retried forever as "the nearest tree".
- Won't vandalize player builds made of log blocks (cabins, fences, etc.):
  before chopping, it checks whether the found log has leaves touching it;
  if not, it walks the chain of connected same-type logs (up to 7 total,
  including the one it found) looking for one with adjacent leaves. If one
  turns up, it confirms this is a real tree and chops the *original* log
  found (not the one where leaves were spotted). If none of the 7 has
  leaves, it's treated as a built structure - that log (and anything within
  7 blocks of it) is skipped and it searches for a different tree instead.
- After finishing (or running out of) one tree, it searches again - but
  only for the same wood type as the first tree - for up to 10 seconds
  before giving up and stopping early with however many logs it has.
- Progress/results are console/log-only, same reasoning as the build
  command above. "Meow, stop." cancels an in-progress gather.
- Also stops itself automatically if a land-protection plugin replies with
  a "you're not allowed to break blocks here"/"don't have permission to
  break" message (e.g. WorldGuard), instead of uselessly retrying the same
  protected spot.

Attack hostile mobs notes ("Meow, toggle attack mode." / control panel
checkbox):
- While enabled, checks every 150ms for the nearest hostile mob (zombie,
  skeleton, creeper, spider, slime, etc. - anything minecraft-data classifies
  as type "hostile", plus slimes specifically since they're classified as
  type "mob" instead) within 15 blocks and fights it; does nothing if no
  hostile is in range. Turning it off immediately stops all movement from
  this behavior.
- Equips whatever sword is available before an axe (axes remain the tool of
  choice for wood-gathering) - re-checked every combat tick, so it'll switch
  weapons mid-fight if inventory changes. Live-tested by giving the bot a
  sword only, an axe only, and both together (with the axe already held) -
  correctly used the sword whenever one was available.
- Holds at ~3 blocks from the mob: too far -> sprints in (so it doesn't fall
  behind a mob trying to keep its range, e.g. a fleeing skeleton), too close
  -> backs away, right at ~3 blocks -> holds position and waits for the
  attack cooldown. Only ever swings at 3 blocks or closer, never while still
  closing in.
- Uses knockback hits: once the (approximate) attack cooldown has elapsed,
  it starts sprinting, waits briefly for that to register server-side (an
  instant sprint+swing wasn't reliably getting the knockback bonus), lands
  the hit while sprinting (vanilla gives much stronger knockback on a
  sprinting hit), then immediately stops closing distance - previously it
  kept walking forward for another 150ms after the swing, chasing right back
  into the mob it had just knocked away (most visible against creepers,
  where it looked like the knockback wasn't pushing them back far enough).
  Creepers specifically also get an extra backward retreat after each hit
  for additional safety margin against their explosion.
- Jumps continuously while closing distance (chasing or attack-lunging)
  instead of getting stuck against ledges - players (unlike most mobs) don't
  auto-step up a full block, so plain forward movement alone would just stop
  dead at any 1-block obstacle in the way. A smarter "only jump when actually
  blocked" version (based on a physics collision flag) didn't reliably catch
  it in practice, so this trades a bit of unnecessary hopping for something
  that actually works.
- The cooldown timer is a fixed ~625ms approximation of vanilla sword
  timing, since mineflayer doesn't expose the real per-weapon attack
  cooldown - actual timing may be slightly off for non-sword weapons or
  bare-handed fighting.

Local test server (for testing without ggsmp.net's flaky connection):
- A Paper 1.21.11 server lives at ~/mc-test-server (outside this repo -
  large jar + generated world data, not meant to be committed). Start it
  with: cd ~/mc-test-server && java -Xmx2G -Xms1G -jar paper-1.21.11.jar
  --nogui
- It's configured offline-mode=false (required - this bot doesn't do real
  Microsoft auth) and generates a superflat world in a forest biome
  (features enabled) so trees spawn naturally for wood-gathering tests,
  plus normal mob spawning for combat tests. spawn-protection is 0 so the
  bot can dig/build near spawn.
- To point the bot at it: copy server-config.local.json over
  server-config.json (or use the control panel's Save Server fields:
  host=localhost, port=25565, leave hubNpcName blank - no lobby NPC needed
  locally). Copy server-config.json back from the ggsmp.net settings (or
  re-enter them) to switch back.
- Stop the server with a graceful `kill <pid>` (it saves on SIGTERM) rather
  than kill -9, to avoid corrupting world data.
